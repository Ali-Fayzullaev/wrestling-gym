## Цель

Владелец за минуту понимает, сколько денег пришло, по каким каналам и группам, и кто должен.

## Что входит

- `/reports` (только `owner`, проверка в action и RLS):
  - выбор месяца (по умолчанию текущий в Алматы);
  - оплаты за месяц: сумма (с учётом сторно), количество, по способам, по группам;
  - должники по группам со списком и суммой ожидаемой оплаты по цене группы.
- Агрегаты считаются SQL-функциями, доступными только `owner`.
- Простые горизонтальные полосы на CSS без библиотек графиков (JS-бюджет).
- Экспорт клиентов и оплат в `.xlsx` и `.csv` через route handler на сервере; защита от CSV/формул injection; имя файла без ПД (`payments-2025-11.xlsx`); rate limit; audit.

## Что не входит

Произвольные отчёты, графики по годам.

## Критерии готовности

1. Интеграция: суммы за месяц на сидах совпадают с ручным подсчётом, сторно уменьшает сумму, оплата 30-го в 23:30 Алматы попадает в правильный месяц.
2. Интеграция: `admin` вызывает функцию отчёта напрямую → отказ БД.
3. Интеграция: экспорт `admin` → 403.
4. Unit: экранирование ячеек `=`, `+`, `-`, `@`.
5. E2E owner: смена месяца, скачивание xlsx и csv, файл открывается и содержит заголовки.
6. Экспорт не увеличивает клиентский JS (проверка `next build`).
7. Lighthouse.
