# 06. Клиенты

## Цель

Администратор находит любого клиента меньше чем за 3 секунды и видит всё о нём на одной карточке.

## Что входит

- `src/lib/phone.ts`: нормализация `8 701 123 45 67`, `+7(701)1234567`, `7011234567` → `+77011234567`; отказ для остального.
- `src/lib/search.ts`: нормализация строки поиска (регистр, `ё→е`, казахские буквы сопоставляются как есть и с упрощёнными аналогами: `қ→к`, `ғ→г`, `ң→н`, `ө→о`, `ұ/ү→у`, `һ→х`, `і→и`, `ә→а`), поиск по фамилии, имени, телефону (цифры без форматирования).
- `/clients`: один серверный запрос с узким набором полей (до 500 записей) из `client_status`; поиск, фильтры (группа, статус, тренер, архив) и сортировка (фамилия, дата окончания) на клиенте без запросов к серверу. Фильтры и сортировка в URL (`?group=<uuid>&status=expired`), строка поиска в URL не пишется (ПД).
- Если клиентов > 500: серверная пагинация (зафиксировать порог константой и тестом; реализовать при необходимости, иначе записать в заметки).
- Строка списка: фамилия имя, группа, статус (`StatusBadge`), дата окончания, кнопка действия.
- `/clients/new` и редактирование: все поля по ТЗ, условное поле «Имя родителя», согласия (чекбоксы → записи `consents`, текст `STUB(D-10)`).
- Предупреждение о дубле телефона с перечислением совпадений (без блокировки).
- `/clients/[id]`: данные, группа, текущий абонемент и статус, история оплат (из шага 07 позже — пока пустой блок с `EmptyState`), история напоминаний (пустой блок), заметка.
- Архив / возврат из архива (подтверждение), audit.
- Полное удаление только `owner`: подтверждение вводом фамилии, причина, audit (без ПД в деталях). Удаление каскадом недопустимо для оплат: если есть оплаты — данные клиента обезличиваются, оплаты остаются (зафиксировать в заметках как решение по умолчанию).

## Что не входит

Отметка оплаты (07), напоминания (09), импорт (10).

## Критерии готовности

1. Unit: `normalizePhone` — 10+ случаев, включая неверные.
2. Unit: поиск находит «Қасымов» по «касымов», «КАСЫМОВ», «қас»; по телефону «7011234» и «+7 701 123».
3. Unit: комбинация фильтров и сортировок.
4. Интеграция: создание клиента с неверным телефоном отклоняется на сервере (Zod) и в БД (check).
5. Интеграция: `admin` не может полностью удалить клиента; `owner` может, audit записан без ПД.
6. E2E mobile: поиск по 150 сидам, результат появляется без сетевых запросов (проверка через `page.on('request')`).
7. E2E: фильтры попадают в URL, открытие ссылки восстанавливает фильтры.
8. E2E: архив скрывает клиента из списка по умолчанию, фильтр «Архив» показывает.
9. E2E: предупреждение о дубле телефона.
10. Экран списка: 1 запрос к БД; карточка: ≤ 3.
11. В URL нет телефонов и имён (e2e проверяет все переходы).
12. Lighthouse mobile `/clients`: Performance 90+, INP визуально мгновенный на поиске.
