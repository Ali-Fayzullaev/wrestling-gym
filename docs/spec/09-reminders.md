# 09. Напоминания через WhatsApp

Статус: done
Зависит от: 08, D-05 (до решения — шаблоны и дни по умолчанию)
Ветка: `step/09-reminders`
Навыки: `backend-development`, `ui-ux-design`, `secure-coding`, `browser-verification`

## Цель

Напоминание об оплате открывается в WhatsApp с готовым текстом в два нажатия, а система честно фиксирует только то, что знает: чат был открыт.

## Что входит

- `src/lib/whatsapp.ts`: `buildWaLink(phone, text)` → `https://wa.me/77011234567?text=<encodeURIComponent>`.
- `src/features/reminders/template.ts`: подстановка `{имя}`, `{дата_окончания}`, `{сумма}`, `{группа}`, `{название_зала}`; неизвестная переменная остаётся как есть и подсвечивается в предпросмотре; результат без лишних пробелов. Для ребёнка обращение к родителю (`parent_name`), если указан.
- Тип напоминания по `days_left`: `before_7`, `before_1`, `overdue` (дни из `settings.reminder_days`, `STUB(D-05)`).
- Кнопка «WhatsApp»: Server Action записывает `reminder_events` (`chat_opened`, кто, когда, шаблон; `on conflict (payment_id, kind) do nothing`), затем открывает ссылку. Ссылка открывается синхронно по клику (чтобы браузер не блокировал), запись события — параллельно, с повтором при ошибке сети.
- Подпись в строке после нажатия: «Чат открыт 14:32». Отдельная кнопка «Отметить отправленным» → `marked_sent`.
- Экран «Напоминания»: вкладки «Сегодня», «Просроченные», «История» (события с фильтром по дате и сотруднику).
- Подсказка на экране: «Отправляйте только с номера зала через WhatsApp Business».
- Шаблоны (только `owner`): список, редактирование, предпросмотр на реальном клиенте из сидов, audit изменений.
- Настройка дней напоминаний (только `owner`). Дни и шаблоны редактируются на одном экране, который открывается из «Настройки → Напоминания» (D-11). Типы показываются словами: «Первое напоминание (за 7 дней)», «Второе (за 1 день)», «В день окончания».
- История напоминаний в карточке клиента.

## Что не входит

Любая автоматическая отправка, WhatsApp API, боты.

## Критерии готовности

1. Unit: `buildWaLink` — номер без `+`, кириллица и казахские буквы, переносы строк, `&` и `#` закодированы.
2. Unit: подстановка шаблона, неизвестная переменная, отсутствующая сумма.
3. Интеграция: два нажатия → одна запись события; другой тип для того же абонемента → вторая запись.
4. Интеграция: `marked_sent` только из `chat_opened`; обратный переход и изменение других полей запрещены.
5. Интеграция: `admin` не может менять шаблоны и дни.
6. E2E: клик «WhatsApp» открывает `wa.me` с ожидаемым текстом (перехват `popup`/навигации), строка показывает «Чат открыт ЧЧ:ММ», клиент уходит из «Напомнить сегодня».
7. E2E: нигде в интерфейсе нет слов «отправлено»/«доставлено» до ручной отметки (поиск по тексту страницы).
8. E2E: предпросмотр шаблона.
9. `/security-review` (ПД в ссылке уходит только в WhatsApp, не в логи и аналитику).

Решения шага:

- Ссылки `wa.me` собираются на сервере (`buildReminderLink` в `features/reminders/service.ts`) и приходят в остров готовой строкой. Код шаблонов и текстов напоминаний в JS `/today` не попадает. Кнопка «WhatsApp» — обычная ссылка `<a target="_blank" rel="noopener noreferrer">`: браузер открывает её в самом клике и не блокирует как всплывающее окно. Запись события идёт параллельно, при сетевой ошибке повтор через 1, 3 и 9 с, затем подпись «Не удалось записать» с кнопкой «Повторить».
- После записи события Server Action делает `revalidatePath("/today")`: строка и счётчик «Напомнить сегодня» уходят вместе, потому что оба берутся из `reminders_due()`. В JS счётчики не правятся. Подпись «Чат открыт ЧЧ:ММ» видна в строке, пока ответ сервера не пришёл; дальше событие видно на вкладке «Сегодня» экрана «Напоминания» (раздел «Чаты, открытые сегодня»), там же кнопка «Отметить отправленным».
- Шаблоны — постоянный набор из трёх, по одному на тип (`unique (kind)`); владелец меняет только текст. INSERT шаблонов и смена `kind` отозваны у всех, политика вставки удалена (тест `db-access.test.ts` переписан под это правило).
- `today_screen()` дополнен: у строк «Напомнить» есть абонемент, тип, телефон и кому он принадлежит; у экрана — контекст напоминаний (название зала, дни, шаблоны). Счётчики и списки по-прежнему из `reminders_due()` и `paid_today()`.
- Настройки дней и текстов сохраняются одной функцией `update_reminder_settings()` в одной транзакции с audit. Второе напоминание можно выключить (пустое поле); первое всегда больше второго. Экран: `/settings/reminders` (только `owner`, в карте доступа маршрутов); общий раздел «Настройки» появится в шаге 12 (D-11).
- Навигация: «Напоминания» в боковом меню и на экране «Ещё» у всех, «Настройки напоминаний» в разделах владельца.
- `STUB(D-05)`: дни 7 и 1 и тексты-заглушки из миграции шага 02 остаются до решения заказчика.

## Заметки на будущее

- Вкладка «Просроченные» открывает чат шаблоном «В день окончания», а событие уникально по `(payment_id, kind)`: повторное напоминание должнику в другой день не создаёт новой записи, в истории остаётся первое открытие. Если заказчику нужны повторные напоминания должникам (D-05), нужен отдельный тип или ключ с датой.
- Бюджет JS: `/clients` 149,1 КБ из 150, `/today` 146,6. Общий код всех экранов (меню, `ru`) вырос на ~1 КБ в этом шаге; следующее добавление в общий макет нужно мерить сразу.
- Локально под высокой нагрузкой (load average 12–15 на 8 ядрах) полный e2e давал случайные падения на desktop в разных тестах (ответ Server Action дольше 5 с); на спокойной машине `pnpm check` зелёный. В своих тестах ожидания ответа сервера 15 с.
- Текст-заглушка «В день окончания» говорит «закончился», хотя отправляется в последний день абонемента. Поправит владелец в настройках или заказчик в D-05.
