## Цель

Единый визуальный язык и каркас интерфейса, чтобы все бизнес-экраны собирались из готовых частей и сразу были быстрыми, доступными и одинаковыми в обеих темах.

## Что входит

- Токены цвета в `globals.css` (светлая и тёмная тема, `oklch`), включая статусные. Акцент: насыщенный красный на графите, пометка `STUB(D-01)`.
- Проверка контраста AA для всех пар текст/фон (unit-тест, считающий контраст из токенов, или зафиксированная таблица с результатами).
- Шрифт с кириллицей и казахскими буквами через `next/font` (например, Inter или Manrope с subsets `cyrillic`, `cyrillic-ext`, `latin`; проверить наличие ә ғ қ ң ө ұ ү һ і), `tabular-nums` утилита.
- Переключатель темы (светлая / тёмная / системная) без мигания.
- `src/lib/format.ts`: `formatMoney(25000) → "25 000 ₸"`, `formatDate(date, today) → "18 ноября"` (год, если не текущий), время «14:32». Часовой пояс `Asia/Almaty`.
- `src/i18n/ru.ts` и хелпер `t()` с типобезопасными ключами.
- Компоненты shadcn/ui: button, input, label, select, dialog, sheet, dropdown-menu, tabs, toast (sonner), skeleton, badge, checkbox, table.
- Свои компоненты: `StatusBadge`, `Money`, `DateText`, `EmptyState`, `StatCard`, `PageHeader`, `ConfirmDialog`, `ListSkeleton`, `ResponsiveDialog` (sheet на мобильном, dialog на компьютере).
- Макет приложения `(app)/layout.tsx`: нижнее меню на мобильном (Сегодня, Клиенты, Группы, Ещё) с `safe-area`, боковое меню на `md+`, активный пункт, предзагрузка ссылок.
- Страница `/dev/ui` (только в dev) со всеми компонентами во всех состояниях для визуальной проверки.
- Пустые страницы-заглушки маршрутов меню с `loading.tsx` и `error.tsx`.

## Что не входит

Бизнес-логика, данные из БД.

## Критерии готовности

1. Unit: `formatMoney`, `formatDate` (включая смену года, полночь в Алматы против UTC).
2. Unit: контраст всех текстовых пар токенов ≥ 4,5:1 в обеих темах.
3. E2E mobile: нижнее меню видно, 4 пункта, переход работает, область нажатия ≥ 44×44 px.
4. E2E desktop: боковое меню видно, нижнего нет.
5. E2E: переключение темы сохраняется после перезагрузки, нет мигания (класс темы есть в первом HTML).
6. E2E: `StatusBadge` содержит текст статуса (не только цвет).
7. Навигация с клавиатуры по меню, фокус виден (скриншот).
8. Lighthouse mobile на `/today` (заглушка): Accessibility 95+, CLS < 0,05; шрифт без скачка.
9. Скриншоты `/dev/ui` в 390 и 1440, светлая и тёмная.

## Решения шага

- Тема хранится в cookie `theme`, класс ставит встроенный скрипт в `<head>` (`src/lib/theme.ts`). Читать cookie на сервере нельзя: корневой layout стал бы динамическим, а `/login` должен остаться статическим (○). Поэтому в первом HTML от сервера класса нет; критерий 5 проверяется тем, что класс есть до отрисовки `<body>`.
- Переключатель темы только в «Ещё» (как в навыке ui-ux-design); в боковом меню пункт «Ещё».
- «Выйти» теперь обычная HTML-форма с POST на route handler `/auth/sign-out` (проверка same-origin, 303 на `/login`), а не Server Action: ноль клиентского JS, полная загрузка страницы после выхода получается сама.
- `cn` с таблицами под проект (`cn build`, `cn.build.ts`, `src/lib/cn-tables.ts`; `withCn` в `next.config.ts` пересобирает их при `build`/`dev`, тест падает, если файл устарел). Импорт голого `cn` запрещён правилом ESLint.
- `/dev/ui` включается в `next dev` или переменной `ENABLE_DEV_UI=1` (её ставит e2e-сервер); в production без переменной 404. Тексты витрины в `src/i18n/dev-ui.ts`, чтобы не попадать в клиентские бандлы.
- `error.tsx` и `loading.tsx` общие на уровне `(app)` (покрывают все пункты меню); у `/today` свой скелетон. Отдельные `error.tsx` на маршрут дублировали бы клиентский чанк.
- Шрифт Inter: предзагружается только кириллица; latin и cyrillic-ext (казахские буквы, U+0460–052F) подгружаются по `unicode-range`. Предзагрузка всех трёх файлов (93 КБ) задерживала LCP примерно на 0,5 с.
- Кольцо фокуса графитовое, не красное: красная рамка путалась с полем с ошибкой.

## Заметки на будущее

- Бюджет JS: фреймворк Next 16 + React 19 занимает около 133 КБ, движок `cn` около 9 КБ. Сейчас его нет в первой загрузке маршрутов приложения: меню, `ThemeToggle` и `error.tsx` собирают классы без `cn`, «Выйти» серверный. Первый клиентский компонент с `Button`/`Input` (формы шагов 05–07, «Оплатил») вернёт `cn` и даст около 150–151 КБ. Варианты: формы как серверные компоненты с минимальным клиентским островом; ленивая загрузка формы (sheet открывается по нажатию); пересмотр бюджета. Тест `first-load-js.spec.ts` покажет.
- `sonner` (около 12 КБ) не в общем layout: `Toaster` монтируется только на экранах с уведомлениями (сейчас `/dev/ui`). Шагу 07 для «Оплатил» лучше грузить его лениво.
- LCP по Lighthouse mobile 2,0–2,65 с при цели 1,5 с, первая отрисовка 0,8–1,2 с; основное — задержка рендера (была и на шаге 03, 2,2 с на `/login`). Разобрать в шаге 13.
- Шаг 13, CSP: встроенный скрипт темы требует hash в `script-src` (nonce сделал бы страницы динамическими). Текст скрипта постоянный, hash считать от `themeInitScript`.
- Next 16 оставляет прошлые экраны в DOM скрытыми после клиентского перехода: в e2e искать только видимые элементы (`actorRole` в `tests/e2e/support/auth.ts`).
- React 19 сбрасывает неуправляемые поля формы после завершения действия; заголовки ответа приходят раньше. В e2e после отправки ждать окончания действия (`submitLogin`), иначе следующий ввод теряется.
- `Field` из шага 03 остался на страницах входа (не трогал, чтобы не менять их JS); новые формы собирать из `Input` + `Label`.
- `/forbidden` не переоформлен под токены (простая страница, работает в обеих темах через `color-scheme`).
