# 00. Обзор проекта

Статус: in-progress

## Что строим

Внутренний веб-сервис для зала греко-римской борьбы в Шымкенте, который заменяет бумажную тетрадь: клиенты, группы, абонементы, оплаты, ежедневные напоминания об оплате через WhatsApp (полуавтомат, wa.me) и отчёты для владельца.

Полное ТЗ: [../prompt.md](../prompt.md). Этот файл — короткая выжимка и план; при расхождении верно ТЗ, а расхождение исправляется здесь.

## Проблема

Администратор пишет в тетрадь имя, телефон, «+» за оплату и подпись. Не видно, у кого заканчивается абонемент, кто должен, сколько денег пришло. Напоминают по памяти. В зале 100–200 спортсменов в группах по 20–30, много детей (телефон родителя).

## Цели

1. Клиенты, группы, абонементы и оплаты в одном месте.
2. Каждый день список «Напомнить сегодня» и WhatsApp в два нажатия.
3. Владелец видит должников, оплаты за месяц, состояние групп.

## Роли

| Роль | Может |
| --- | --- |
| `owner` | всё: сотрудники, группы, цены, отчёты, экспорт, журнал, полное удаление |
| `admin` | клиенты, просмотр групп, отметка оплаты, напоминания |

Клиенты в систему не входят. Регистрации нет.

## Ключевые правила предметной области

- **Статус абонемента** (одна SQL-функция, дата в `Asia/Almaty`): `active` > 7 дней, `expiring` 0–7 дней, `expired` прошла, `none` оплат не было.
- **Оплаты только добавляются.** Ошибка исправляется сторно (отрицательная сумма + причина + ссылка). Отмена в течение 10 минут = сторно «отменено сразу».
- **Идемпотентность**: `payments.idempotency_key unique`; `reminder_events unique (payment_id, kind)`.
- **Продление** (D-03, шаг 18): от старой даты окончания, в том числе при опоздании; пропал дольше месяца → от даты оплаты. Дату «до» при оплате можно изменить (D-16).
- **WhatsApp**: только ссылка `wa.me` с готовым текстом из шаблона. Нажатие = событие «Чат открыт», не «отправлено». Админ может отдельно отметить «Отправлено».
- **Телефон**: `+77XXXXXXXXX`, дубли разрешены с предупреждением.
- **Клиенты** архивируются, полное удаление только у владельца с причиной.
- **Всё управляется из «Настроек»** (требование заказчика, D-11): название зала, номер WhatsApp, группы (название, тренер, расписание, цена, лимит мест), дни и тексты напоминаний, сотрудники. Владелец меняет это сам, без программиста. Простые слова вместо терминов, у каждого поля короткая подсказка, после сохранения понятное подтверждение.

## Модель данных

`staff`, `groups`, `clients`, `consents`, `payments` (оплаты и сторно), `reminder_events`, `message_templates`, `settings` (одна строка), `audit_log`. Статус абонемента и счётчики «Сегодня» считают SQL-функции `client_status` и `dashboard_counts`. ER-список, права по ролям и функции: [02-database.md](02-database.md#схема-er-список).

## Технологии

Next.js (App Router, RSC, Server Actions), TypeScript strict, Tailwind + shadcn/ui, lucide-react, Supabase (Postgres, Auth, RLS, CLI-миграции), Zod, Vitest, Playwright, GitHub Actions, Vercel. Регионы Vercel Functions и Supabase совпадают (`fra1` + `eu-central-1`).

## Нефункциональные требования

| Область | Требование |
| --- | --- |
| Скорость | LCP < 1,5 с, INP < 100 мс, CLS < 0,05 на 4G; JS ≤ 150 КБ gzip на маршрут; 2–3 запроса к БД на экран |
| Lighthouse mobile | Performance 90+, Accessibility 95+, Best Practices 95+ |
| Безопасность | RLS на каждой таблице, append-only в БД, ПД не в логах/URL, заголовки CSP/HSTS, rate limit |
| Надёжность | ежедневный `pg_dump`, проверенное восстановление |
| UX | mobile-first 390 px, 44×44 px, тёмная/светлая тема, статус цветом и текстом |

## Критерии приёмки всего проекта

- Администратор на телефоне находит клиента < 3 с и отмечает оплату < 10 с.
- Напоминание открывается в WhatsApp с готовым текстом в два нажатия.
- Двойное нажатие «Оплатил» не создаёт двух оплат.
- `admin` не видит денежные отчёты, прямой запрос получает отказ от БД.
- Оплату нельзя изменить или удалить ни из интерфейса, ни прямым запросом.
- Lighthouse mobile: Performance 90+, Accessibility 95+, Best Practices 95+.
- Все экраны удобны на 390 и 1440 px, в консоли нет ошибок.
- Есть ежедневный бэкап и проверенное восстановление.

## Стоимость (сообщить заказчику)

- Vercel Hobby только для некоммерческого использования: нужен Pro (~$20/мес) или другой хостинг (D-06).
- Supabase Free: 500 МБ хватит, но проект засыпает после недели без запросов и бэкапов нет; Pro ~$25/мес (D-06).
- WhatsApp через wa.me бесплатен. Домен `.kz` ~5–10 тыс. ₸/год.
