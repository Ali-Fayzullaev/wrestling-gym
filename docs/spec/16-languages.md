# 16. Казахский и узбекский (кириллица)

Статус: done
Зависит от: 15, D-04, D-13
Ветка: `step/16-languages`
Навыки: `ui-ux-design`, `backend-development`, `browser-verification`

## Цель

Интерфейс работает на трёх языках (D-04): русский, казахский, узбекский (кириллица, `uz-Cyrl`). Каждый сотрудник видит сервис на своём языке.

## Что входит

- Словари `src/i18n/kk.ts` и `src/i18n/uz.ts` той же формы, что `ru.ts`; тип словаря выводится из `ru`, отсутствующий ключ ловит `tsc`. Убрать `STUB(D-04)` из файлов `src/i18n/*`.
- Выбор языка. По умолчанию до решения D-13: каждый сотрудник выбирает язык в своём профиле, хранится в БД, по умолчанию русский. Переключатель на экране «Ещё» под блоком «Тема», того же вида (три сегмента: «Русский», «Қазақша», «Ўзбекча», каждое название на своём языке; владелец просил именно это место); без входа (страница входа) язык из cookie или `Accept-Language`, иначе русский. `<html lang>` по выбранному языку.
- Даты, числа и суммы в тенге через `Intl` с локалью `ru-KZ`, `kk-KZ`, `uz-Cyrl-UZ`; дни недели и месяцы в отчётах и на «Сегодня».
- Напоминания в WhatsApp. По умолчанию до решения D-13: язык клиента (поле в карточке, по умолчанию русский) и три версии каждого шаблона, владелец редактирует все три в «Настройках». Без решения D-13 эта часть делается заглушкой `STUB(D-13)`: шаблоны остаются одноязычными.
- Экспорт xlsx/csv: заголовки на языке того, кто выгружает.
- Вёрстка: казахские и узбекские строки длиннее, проверить все экраны на 390 и 1440 px, ничего не обрезается и не переносится криво.
- Переводы помечаются «черновик» до вычитки носителем языка (D-13, п. 3).

## Что не входит

Латиница для узбекского. Перевод текстов, которые вводит владелец (названия групп, тексты шаблонов): их владелец пишет сам.

## Критерии готовности

1. Сотрудник переключает язык, все экраны, ошибки, пустые состояния и подсказки на выбранном языке, без смешения.
2. Тест: в `kk` и `uz` есть все ключи `ru`, нет пустых строк.
3. Даты и суммы форматируются по языку (unit-тесты с фиксированным `now`).
4. E2E на каждом языке проходит основные сценарии («Сегодня», оплата, клиенты) на 390 и 1440 px; скриншоты в `docs/spec/screenshots/16/`.
5. JS первой загрузки остаётся ≤ 150 КБ gzip: словарь грузится на сервере, в клиент уходят только нужные строки.
6. `pnpm check` зелёный.

## Результаты

- Словари `src/i18n/ru.ts` (эталон), `kk.ts`, `uz.ts`: один объект на язык, разделы верхнего уровня (`nav`, `clients`, `payments`…). Тип `Messages` выводится из `ru` (`src/i18n/messages.ts`): недостающий ключ ловит `tsc`. Тексты только данные: строки, списки и формы числа; параметры пишутся `{name}` (`fmt`), формы числа выбирает `Intl.PluralRules` (`plural`). Прежние модули `src/i18n/<область>.ts` удалены вместе с `STUB(D-04)`; `dev-ui.ts` остался русским (витрина только для разработки).
- Загрузка на сервере. Язык запроса ставит proxy в заголовок `x-app-locale` (браузерный заголовок всегда перезаписывается): у сотрудника из профиля (`current_staff_access()` теперь возвращает и `locale`, лишнего запроса нет), у гостя из cookie `locale`, затем `Accept-Language`, иначе русский. `getI18n()` читает заголовок; Server Components, Server Actions и route handlers берут словарь целиком. Клиентские компоненты получают только нужные разделы через `<Texts ns={[...]}>` (данными в RSC, не JS) и читают их `useText(ns)`. Три словаря в браузерный бандл не попадают (`dictionaries.ts` с `server-only`).
- Выбор языка: экран «Ещё», под «Темой», три сегмента «Русский / Қазақша / Ўзбекча», каждый на своём языке. `set_my_locale()` (security definer) меняет только строку вызывающего; гость, отключённый сотрудник и сотрудник с временным паролем получают отказ; прямой UPDATE колонки запрещён правами. После сохранения страница перезагружается, cookie следует профилю, поэтому вход после выхода остаётся на выбранном языке. `<html lang>` по языку (`uz-Cyrl` для узбекского).
- Даты и суммы. Таблицы CLDR (месяцы, дни недели, порядок слов) в `src/lib/format.ts`, а не `Intl` во время работы: в Chromium нет данных казахской локали (`Intl` выдаёт «M11 18» и «1,234,567»), для узбекского браузер и Node расходятся в порядке слов, из-за этого была ошибка гидратации. Unit-тест сверяет таблицы с `Intl` Node (полный ICU) по всем месяцам, отчётным месяцам, дням недели и группам разрядов. Узбекский день недели взят в виде «чоршанба, 18 ноябр» (Chrome), а не «ноябр 18, чоршанба» (Node 24). Русские даты другого года теперь с «г.» («18 ноября 2025 г.»), как в CLDR; это видно и в напоминаниях.
- Напоминания: `STUB(D-13)`. Шаблоны одноязычные; дата и сумма в тексте клиенту по-русски (`template.ts`). В «Настройки → Напоминания» добавлена строка, что сообщение уходит на языке шаблона.
- Экспорт xlsx/csv и шаблон импорта: заголовки на языке того, кто выгружает. Распознавание столбцов импорта знает казахские и узбекские заголовки (в том числе из шаблона).
- Черновик: под переключателем на kk и uz надпись, что перевод ещё вычитывается; в начале `kk.ts` и `uz.ts` пометка «ЧЕРНОВИК» (D-13, п. 3).
- Вёрстка: e2e `languages.spec.ts` проходит «Ещё», «Сегодня», клиентов, оплату и карточку клиента на ru, kk и uz (mobile 390 и desktop 1440), без ошибок в консоли; скриншоты в `screenshots/16/`. Скрипт обошёл все 18 экранов на kk и uz при 390 и 1440 px и искал обрезанный текст и горизонтальную прокрутку: после сокращения трёх фильтров списка клиентов (kk «Мәртебелер», «Бапкерлер», «Мұрағатсыз»; uz «Мураббийлар», «Архивсиз») находок нет.
- Тесты: полнота словарей, отсутствие пустых строк и эмодзи, одинаковые `{параметры}` во всех формах, доля непереведённых строк меньше 10 %; форматирование по языку с фиксированным `now`; выбор языка из `Accept-Language`; интеграция `locale-db.test.ts` (отказы гостю, отключённому, временному паролю, чужой строке, неверному языку, прямому UPDATE, гонка); e2e: язык после выхода, язык профиля на другом устройстве, ошибка входа на языке страницы, заголовок браузера не меняет язык сотрудника, экспорт с казахскими заголовками.
- Первый прогон CI нашёл, что «Настройки → Сотрудники» не передавали клиентским компонентам разделы `staff` и `roles` (`useText` бросает ошибку, страница падала). Исправлено; проверено, что каждое `useText(ns)` получает раздел из layout или со своей страницы, и повторный обход всех экранов на kk и uz ищет и страницу ошибки.
- Lighthouse mobile (локальная production-сборка, `simulate`, казахский): `/login` 100 / 100 / 100, LCP 0,8 с; `/today` 94 / 100 / 100, LCP 3,1 с; `/more` 100 / 100 / 100; CLS 0. JS первой загрузки снизился, потому что тексты больше не лежат в клиентских бандлах: `/settings` 149,0 → 144,3 КБ, `/clients` 148,5 → 147,6 КБ, `/login` 145,5 → 144,3 КБ; максимум 147,6 КБ.
- Локальный `pnpm check`: типы, линтер, формат, unit 653, интеграция 513, сборка зелёные. В e2e под нагрузкой падают чужие сценарии с таймаутами БД `57014` (как в шаге 15); упавшие отдельно проходят, в том числе все сценарии языков и бюджет JS. Решающий прогон в CI.
