## Что входит

### 1. Семейный блок на экране «Напоминания»

- Вкладки «Сегодня» и «Просроченные»: дети одного родителя, которым сейчас нужно напоминание, показываются одним блоком, как на «Сегодня» (шаг 21): заголовок «Айгуль (мама): Арман, Дана», одна кнопка WhatsApp на телефон родителя, текст из шаблона `family` с переменной `{дети}`, язык родителя, переключатель языка из шага 20.
- Группировка одна на оба экрана: `groupDueRows()` переносится из `src/features/today/service.ts` в `src/features/reminders/` (там, где живёт логика напоминаний), «Сегодня» импортирует её оттуда. Поведение «Сегодня» не меняется, это проверяют его тесты.
- На «Просроченных» в блок попадают только просроченные дети родителя; дети с другим видом напоминания остаются на вкладке «Сегодня», как и сейчас. События пишутся с видом каждого ребёнка (`overdue`), шаблон `family` общий.
- Нажатие WhatsApp: «Чат открыт» по каждому ребёнку из блока через `record_family_reminder_opened()` (шаг 21). Повтор и параллельные нажатия не создают дублей: `reminder_events (payment_id, kind)` не меняется.
- «Отметить отправленным» у блока отмечает события всех детей блока одним вызовом и одной транзакцией: или все, или ни одного. Повтор ничего не меняет. Ребёнок, по которому чат ещё не открывали, не отмечается (отметка без «Чат открыт» сейчас тоже запрещена).
- Если в блоке часть детей уже отмечена, блок показывает, кто отмечен, а кто нет; кнопка отмечает оставшихся.
- Вкладка «История» не меняется: события остаются по ребёнку.
- Экран по-прежнему делает 2 запроса к БД: роль и одна вкладка `reminders_screen()`. Группировка в TypeScript по уже полученным строкам, без N+1.

### 2. Архив родителя

- Кнопки «В архив» и «Вернуть из архива» на карточке родителя `/parents/[id]`. Могут `owner` и `admin`, как архив клиента.
- Серверная функция `set_parent_archived(p_parent_id, p_archived)` по образцу `set_client_archived()`: повтор ничего не меняет, журнал `parent.archive` / `parent.restore` только с UUID, без имени и телефона.
- `STUB(D-23)`: родителя нельзя отправить в архив, пока у него есть дети не в архиве. Отказ БД `parent_has_active_children` и понятный текст: «Сначала отправьте в архив детей или привяжите их к другому родителю». Так ребёнок в работе не остаётся с архивным родителем, а вопрос, куда тогда уходят напоминания, не возникает. Ждёт подтверждения заказчика (D-23).
- Архивный родитель не находится в поиске родителя в форме клиента (так уже сделано в шаге 21) и помечен «В архиве» на своей карточке и в блоке «Родитель» карточки ребёнка.

### 3. Удаление родителя

- Кнопка «Удалить» на карточке родителя только у `owner`. Интерфейс для `admin` её не показывает, но защита в БД: RLS `parents_delete` и проверка роли в функции.
- Серверная функция `delete_parent(p_parent_id, p_reason, p_name)` по образцу `delete_client()`: причина из того же списка (`duplicate`, `created_by_mistake`, `client_request`, `other`), подтверждение вводом имени родителя, журнал `parent.delete` с причиной, без ПД.
- Удалить можно только родителя без детей, включая архивных (обезличенные удалённые клиенты уже отвязаны, `parent_id = null`). Есть дети: отказ БД `parent_has_children` и текст: «У родителя есть дети. Сначала удалите их или привяжите к другому родителю». Внешний ключ `on delete restrict` остаётся последней защитой.
- После удаления переход на `/clients` с подтверждением. История напоминаний детей не страдает: события висят на детях, не на родителе.
- Тексты кнопок, подтверждений и ошибок на ru, kk, uz.
- `docs/admin-guide.md`: как отправить родителя в архив и как владельцу удалить ошибочно созданного родителя.

## Что не входит

- Ответы по D-20, D-21, D-22 (см. выше).
- История напоминаний семьи на карточке родителя: остаётся в карточке каждого ребёнка (заметка шага 21).
- Отдельный список родителей с фильтром «В архиве»: на карточку родителя попадают из карточки ребёнка.
- Проверка переноса на копии production-бэкапа: делает владелец ключа по `docs/runbook.md`, кода не требует.
- Перенос ребёнка к другому родителю: уже есть в форме ребёнка (шаг 21).
