# 14. Приёмка с заказчиком

Статус: todo
Зависит от: все
Ветка: `step/14-acceptance`

## Цель

Подтвердить на настоящем телефоне администратора у входа в зал, что сервис заменяет тетрадь и выполняет все критерии приёмки.

## Что входит

- Сценарий приёмки `docs/acceptance.md` с шагами и местом для отметок.
- Прогон на телефоне администратора (реальный Android/iPhone, мобильный интернет) и на компьютере владельца.
- Замер времени: поиск клиента, отметка оплаты, открытие напоминания.
- Список замечаний заказчика → задачи (исправления в этом шаге, если мелкие; иначе новые шаги в `00-overview.md`).
- Краткая инструкция для администратора (1 страница, со скриншотами на сидах) `docs/admin-guide.md`.
- Финальная проверка `90-open-decisions.md`: все решения закрыты или явно отложены заказчиком.

## Критерии приёмки

| # | Критерий | Как проверяем | Результат |
| --- | --- | --- | --- |
| 1 | Найти клиента < 3 с | секундомер на телефоне, 5 попыток | |
| 2 | Отметить оплату < 10 с | секундомер, 5 попыток | |
| 3 | Напоминание в WhatsApp в два нажатия с готовым текстом | на телефоне администратора, номер зала | |
| 4 | Двойное нажатие «Оплатил» не создаёт двух оплат | e2e + ручная попытка | |
| 5 | `admin` не видит отчёты; прямой запрос получает отказ БД | e2e + интеграционный тест | |
| 6 | Оплату нельзя изменить или удалить | интеграционный тест + UI | |
| 7 | Lighthouse mobile 90+ / 95+ / 95+ | отчёт из шага 13 | |
| 8 | Экраны удобны на 390 и 1440 px, консоль без ошибок | ручной обход + e2e | |
| 9 | Ежедневный бэкап и проверенное восстановление | runbook, журнал Actions | |
