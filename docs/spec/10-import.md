# 10. Импорт из тетради (CSV, Excel)

Статус: done
Зависит от: 06
Ветка: `step/10-import`
Навыки: `backend-development`, `secure-coding`, `ui-ux-design`

## Цель

Перенести существующих клиентов из тетради (переписанной в Excel) за несколько минут, без дублей и без потери данных.

## Что входит

- Загрузка `.csv` (UTF-8 и Windows-1251, разделители `,` и `;`) и `.xlsx` до 2 МБ, только `owner` (и `admin`, если D-09 разрешит).
- Парсинг на сервере. Библиотека для xlsx выбирается по размеру и поддержке (обосновать в PR), в клиентский бандл не попадает.
- Столбцы: фамилия, имя, телефон, группа, дата окончания абонемента; сопоставление заголовков по синонимам («Фамилия», «Surname», «Тегі»…), ручное сопоставление, если не распознано.
- Предпросмотр: таблица со статусом строки (новая, дубль — уже есть, ошибка) и текстом ошибки рядом («Неверный телефон», «Группа не найдена — будет создана?»).
- Импорт в транзакции. Дата окончания из тетради создаёт запись `payments` типа `import_balance` (добавить тип отдельной миграцией, сумма 0, `period_end` = дата из файла, причина «перенос из тетради»). Так статус считается обычной функцией, а в истории честно видно, что денег системой получено не было.
- Строки с ошибками не импортируются, корректные импортируются одной транзакцией; отчёт показывает пропущенные строки и даёт скачать их файлом для исправления.
- Повторный импорт того же файла не создаёт дублей: ключ дедупликации (нормализованный телефон + фамилия + имя), хеш файла в `audit_log`.
- Ограничение частоты импорта. Audit.
- Шаблон файла для скачивания.

## Что не входит

Импорт истории оплат по месяцам.

## Критерии готовности

1. Unit: парсинг CSV в обеих кодировках и с обоими разделителями; xlsx с датами в разных форматах (`18.11.2025`, число Excel).
2. Unit: сопоставление заголовков по синонимам.
3. Интеграция: импорт 150 строк → 150 клиентов; повтор → 0 новых.
4. Интеграция: строка с ошибкой не импортируется, остальные импортируются; `client_status` для импортированных считается по дате окончания из файла.
5. Интеграция: файл > 2 МБ и неверный тип отклоняются.
6. E2E: загрузка → предпросмотр с ошибками → импорт → клиенты в списке со статусами по дате окончания.
7. Импорт 500 строк < 5 с локально.

Решения шага:

- Библиотека xlsx: `fflate` 0.8.3 (распаковка zip, без зависимостей, релиз май 2026) и собственное чтение первого листа (общие строки, inline-строки, числа). Отклонены: `xlsx` (SheetJS) на npm не обновляется с 0.18.5, свежие версии только с их CDN; `exceljs` 21 МБ и 9 зависимостей; `read-excel-file` обновлялся вчера и тянет 4 зависимости, включая малоизвестные. Парсер только на сервере, в клиентских чанках его нет (проверено по `.next/static`). Защита от zip-бомб: лимит распакованного размера каждой части и суммы, `fflate` не распаковывает больше заявленного размера.
- Файл не хранится: браузер держит его и отправляет на каждом шаге (предпросмотр, смена столбцов, импорт), сервер каждый раз читает заново и не доверяет данным предпросмотра. Лимит тела Server Actions поднят до 2200 КБ (`next.config.ts`).
- Ключ дедупликации: нормализованный телефон + фамилия + имя без учёта регистра, проверяется и в предпросмотре, и в `import_clients` под advisory lock, поэтому параллельный повтор не создаёт дублей. Хеш SHA-256 файла пишется в audit, предпросмотр предупреждает, что файл уже импортировали.
- `import_balance`: отдельная миграция, сумма 0, `method` null (столбец стал nullable, ограничение формы требует способ у оплат и сторно), период: месяц до даты окончания (`STUB(D-02)`). Учитывается в `client_status`, продлении (`record_payment`) и напоминаниях; сторно невозможно; в «Оплатили сегодня» и суммах не участвует.
- Тетрадь не говорит, чей телефон и с какого числа занимается клиент: пишется «свой» и дата импорта, исправляется в карточке.
- Импорт только у `owner` (`STUB(D-09)`): маршрут в карте доступа, Server Action, сервис и функции БД. Вход: кнопка «Импорт» в списке клиентов и пункт «Импорт клиентов» в «Ещё» у владельца.
- Тест критерия 11 шага 06 (`clients.spec.ts`, нет ПД в URL) теперь допускает путь `/clients/import`: ссылка «Импорт» в списке у владельца предзагружается. Путь без данных; проверка имён и телефонов в URL не изменилась.
- Лимит частоты: 10 импортов в час на сотрудника, считается по audit внутри транзакции импорта. Тесты с записью в БД работают от временного владельца, чтобы повторные прогоны не упирались в лимит.

## Заметки на будущее

- Ошибочно импортированную дату окончания нельзя сторнировать (сумма 0); исправляется только новой оплатой, которая продлевает от неё. Если нужна отмена импорта, нужен отдельный тип отмены для `import_balance` или удаление клиента владельцем.
- Столбец «ФИО» одной ячейкой не разбирается: нужно выбрать фамилию и имя из разных столбцов. Если в реальных тетрадях так записано, добавить разбор.
- Предпросмотр не ограничен по частоте (только владелец, ничего не пишет); лимит стоит на импорт.
- Бюджет JS: `/clients` 149,1 КБ из 150. Ссылка «Импорт» в шапке списка добавлена только серверным кодом; в общее меню пункт не добавлен, чтобы не увеличивать общий чанк.
