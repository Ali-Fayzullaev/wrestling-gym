# browser-verification

Тесты зелёные ещё не значит, что экран работает. Перед закрытием шага с интерфейсом посмотреть на него своими глазами.

## Подготовка

1. `pnpm db:reset` (свежие сиды) и `pnpm dev` в фоне.
2. Войти под тестовым `owner`, затем повторить ключевые сценарии под `admin` (учётки из `supabase/seed.sql`).
3. Если MCP `playwright` не подключён: `pnpm test:e2e --headed` и скриншоты из Playwright (`page.screenshot`).

## Что проверить на каждом изменённом экране

Сначала 390×844 (mobile), потом 1440×900 (desktop), в светлой и тёмной теме.

- [ ] Главный сценарий шага проходит руками от начала до конца.
- [ ] Нет горизонтальной прокрутки на 390 px, ничего не обрезано, нижнее меню не перекрывает контент.
- [ ] Области нажатия основных кнопок не меньше 44×44 px.
- [ ] Состояния: загрузка (скелетон без скачка), пусто, ошибка, успех.
- [ ] Навигация с клавиатуры (Tab, Enter, Esc), фокус виден.
- [ ] Консоль: 0 ошибок и 0 предупреждений React (hydration, key).
- [ ] Сеть: экран делает не больше 2–3 запросов к БД, нет повторяющихся запросов, нет ПД в URL запросов.
- [ ] Под `admin` недоступное владельцу не видно, прямой переход по URL даёт отказ.

## Скриншоты

Сохранять в `docs/spec/screenshots/NN/<экран>-<mobile|desktop>-<light|dark>.png`. Только сиды с вымышленными данными, никаких реальных людей.

## Lighthouse

Против production-сборки, не dev: `pnpm build && pnpm start`, затем

```
npx lighthouse http://localhost:3000/<маршрут> --preset=perf --form-factor=mobile --screenEmulation.mobile --throttling-method=simulate --only-categories=performance,accessibility,best-practices --output=json --output-path=./.lighthouse/<маршрут>.json --chrome-flags="--headless"
```

Целевые значения: Performance 90+, Accessibility 95+, Best Practices 95+, LCP < 1,5 с, CLS < 0,05. Для маршрутов за входом использовать сохранённую cookie сессии или замерять после входа через Playwright.

Записать в отчёт шага: оценки, LCP, CLS, размер JS первой загрузки маршрута из вывода `next build`.

## Если что-то не так

Исправить в этом же шаге и добавить тест (e2e или unit), который ловит проблему. Если исправление вне рамок шага, записать в «Заметки на будущее» и сказать в отчёте.
