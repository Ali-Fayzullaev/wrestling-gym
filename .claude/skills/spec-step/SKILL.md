# spec-step

## Начать шаг

1. Прочитать `docs/spec/NN-*.md`, `docs/spec/00-overview.md`, `docs/spec/90-open-decisions.md`.
2. Проверить, что все шаги из «Зависит от» в статусе `done`. Если нет, остановиться и сказать, какой шаг нужен раньше.
3. Проверить решения заказчика, от которых зависит шаг. Нет решения: делать по умолчанию из файла шага с пометкой `STUB(D-NN)`.
4. `git switch main && git pull --ff-only && git switch -c step/NN-name`.
5. В файле шага поставить `Статус: in-progress`, в таблице `00-overview.md` тоже.
6. Коротко (5–10 строк) написать пользователю план шага и сразу начинать работу.

## Вести шаг

- Работать по чек-листу файла шага сверху вниз, отмечая `[x]` по факту.
- Каждый критерий готовности закрывается тестом. Если тест невозможен (например, визуальная проверка), записать, как проверено, и приложить скриншот в `docs/spec/screenshots/NN/`.
- Нашёл что-то вне рамок шага: записать в раздел «Заметки на будущее» файла шага, не делать.
- Возник вопрос к заказчику: добавить в `90-open-decisions.md` новую строку D-NN.

## Закрыть шаг

Шаг закрыт только когда всё правда:

- [ ] Все пункты чек-листа отмечены.
- [ ] `pnpm check` зелёный локально.
- [ ] Проверка в браузере на 390 и 1440 px (если есть интерфейс), консоль без ошибок.
- [ ] Lighthouse mobile записан в отчёт (если есть интерфейс).
- [ ] `/security-review` пройден (если шаг трогает данные, доступ, вход).
- [ ] В diff нет секретов.
- [ ] Статус `done` в файле шага и в `00-overview.md`.
- [ ] Коммит `feat(step-NN): ...`, пуш, PR, CI зелёный.

## Формат отчёта (последнее сообщение чата)

```
## Шаг NN: <название> — готово

PR: <ссылка>   CI: зелёный

Сделано:
- ...

Тесты: unit X, интеграция Y, e2e Z (все зелёные)
Lighthouse mobile: Perf __ / A11y __ / BP __   JS первой загрузки: __ КБ
Security review: пройден / не требовался (почему)

Заглушки и открытые решения:
- STUB(D-NN): ...

Не сделано и почему:
- ...
```

## Промпт для следующего чата

Сразу после отчёта, в блоке кода, чтобы его можно было скопировать целиком:

```
Выполни шаг NN+1 из docs/spec/NN+1-<name>.md по правилам CLAUDE.md и навыка spec-step.
Предыдущий шаг NN смёржен в main (PR #__).
Важно учесть: <1–3 пункта контекста, которых нет в файлах>.
```

Промпт короткий: всё, что можно прочитать в репозитории, в промпт не копировать.
