# secure-coding

Телефоны и данные детей — персональные данные (Закон РК «О персональных данных и их защите»). Утечка хуже, чем падение сервиса.

## Роли и доступ

- `owner`: всё. `admin`: клиенты, просмотр групп, оплата, напоминания; без денежных отчётов, сотрудников, журнала, экспорта.
- Права проверяются дважды: в Server Action (`requireStaff`) и в БД (RLS). Скрытие кнопки не защита.
- Сотрудник с `active = false` теряет доступ на следующем запросе (RLS через `current_staff_role()`, middleware проверяет `staff`).
- Открытой регистрации нет: в Supabase Auth отключён signup, сотрудников создаёт владелец через серверный код с `service_role`.

## Персональные данные

- В URL только UUID. Поиск и фильтры в URL не содержат телефонов и имён (поисковая строка не сохраняется в URL).
- Логи, аналитика, Sentry-подобные сервисы, тексты ошибок: без имён и телефонов. Логировать id и коды ошибок.
- `audit_log.details` без ПД: только id сущностей и названия изменённых полей.
- Экспорт (xlsx/csv) только `owner`, с ограничением частоты и записью в журнал.
- Полное удаление клиента только `owner`: подтверждение, причина, запись в журнале.
- Согласия (`consents`) только добавляются: кто, когда, какой тип.

## Append-only

`payments`, `consents`, `audit_log`: в БД нет политик UPDATE/DELETE и есть триггер, который бросает исключение. Тест: прямой `update`/`delete` от любой роли, включая `owner`, падает.

## Секреты

- `SUPABASE_SERVICE_ROLE_KEY` только в серверном модуле с `import "server-only"`. Никогда в `NEXT_PUBLIC_*`.
- `.env*` (кроме `.env.example`) в `.gitignore`. Значения в Vercel env и GitHub Secrets.
- `.env.example` содержит только имена переменных.

## Ввод

- Весь ввод Server Actions и route handlers через Zod на сервере. Неизвестные поля отбрасываются.
- Телефон нормализуется к `+77XXXXXXXXX`, иначе отказ.
- Импорт файлов: ограничение размера (например, 2 МБ), проверка типа, парсинг на сервере, без формул в ячейках экспорта (экранировать `= + - @` в начале строки — защита от CSV injection).
- SQL только через параметризованные запросы клиента Supabase или SQL-функции; без конкатенации строк.

## Ограничение частоты

Вход (по IP и email), сброс пароля, экспорт, импорт. Реализация: таблица в Postgres или встроенные лимиты Supabase Auth; без новых внешних сервисов без решения.

## Заголовки (next.config / middleware)

- `Content-Security-Policy` с nonce для скриптов, `frame-ancestors 'none'`, `connect-src` только свой домен и Supabase.
- `Strict-Transport-Security: max-age=63072000; includeSubDomains; preload`
- `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`
- `Referrer-Policy: strict-origin-when-cross-origin`
- `Permissions-Policy: camera=(), microphone=(), geolocation=()`

## Резервные копии

Ежедневный `pg_dump` через GitHub Actions по расписанию в приватное зашифрованное хранилище, хранить 30 дней. Восстановление проверено и описано в `docs/runbook.md`.
